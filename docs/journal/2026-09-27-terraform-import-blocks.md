# 2026-09-27: importブロックでコンソールのリソースをTerraformに取り込むときのコツ

## 背景
サーバーレス版は、コンソールで作ってから、Terraformに取り込んだ。ECS版では`terraform import`コマンドを使ったが([ADR-0018](../adr/0018-terraform-import-vs-recreate.md))、今回は`import`ブロックを使った。Terraformのコードを自分で書くのは、今回が初めてだった。

## 流れ
1. `import.tf`に、取り込むリソースの`import`ブロックだけを書く(`to`にコード上の名前、`id`にAWS上の識別子)
2. `terraform plan -generate-config-out=generated.tf`で、実物の設定からコードを自動生成する
3. 生成されたコードを`main.tf`に清書し、`generated.tf`を消す
4. `terraform plan`で`N to import, 0 to add, 0 to change, 0 to destroy`になることを確認する
5. `apply`で取り込む(AWSには変更がなく、stateに書き込まれるだけ)。取り込んだ`import`ブロックは消す

関係の深いリソースを組にして(DynamoDB → ECR → IAM → Lambdaとロググループ → HTTP API)、この流れを繰り返した。

## つまずいたところと、分かったこと
- **生成されたコードは、全項目が出る**: 既定値や`null`の項目も書き出されるので、意味のある項目だけを残す。`region`も出るが、providerの設定と重複するので消す
- **`generated.tf`を消し忘れると、「Duplicate resource」のエラーになる**: 同じリソースが2か所で定義されるため
- **取り込み前に`import`ブロックを消すと危ない**: IAMの組で、`apply`する前に`import`ブロックを消してしまった。そのまま`plan`すると、Terraformはリソースを「新しく作るもの」と判断する。ロールは同名のものがあるのでエラーになるが、インラインポリシーは既存のものを上書きするおそれがあった。S3のstateを直接見て、取り込まれていないことに気づいた
- **変えると作り直しになる項目(ForceNew)に注意**: コンソールで作ったIAMのロールとポリシーは`path = "/service-role/"`にある。書き忘れると、既定値の`/`と比べられて「作り直し」の差分が出る
- **ポリシーの細部も一致させる**: `Sid`や`Version`(Lambdaが書き足したECRのポリシーは`2008-10-17`)が違うだけでも差分になる
- **名前とARNは、受け取る側の項目で決まる**: 同じ`role`でも、Lambda関数はARN、インラインポリシーや付与は名前を求める。生成されたコードに入っている値の形を見て、同じものを返す属性(`.arn`か`.name`か)で置き換える。同じサービスの中なら名前、サービスをまたぐならARNが多い
- **Lambdaの`arn`と`invoke_arn`は別物**: HTTP APIの統合は、関数のARN(`arn`)をそのまま受け付ける。`invoke_arn`にすると、実物と違うので差分が出た
- **自動で変わる値は書かない**: 自動デプロイのステージの`deployment_id`や、Lambdaの`code_sha256`は、コードに書くと後でずれる
- **直打ちの置き換えは、取り込んだあとに行う**: アカウントIDやARNを参照に置き換える変更は、AWSに渡す値が同じなら`plan`がNo changesのまま。単体テストが通ったままリファクタリングするのと同じで、No changesを「テストが通っている」状態として使える。一方、値が変わるもの(権限を絞る変更)は、リファクタリングではなく変更として、別に`apply`する
- **参照すると循環することがある**: ECRのリポジトリポリシーの条件を、Lambda関数のリソースの参照で書くと、「関数を作るにはpullの権限が必要、権限は関数のARNを参照」という循環になる。関数のARNは名前から組み立てられるので、文字列で組み立てて避けた

## 学び
- `-generate-config-out`は、「コンソールで設定したことが、HCLではどう書かれるか」を知る教材になる。いきなりコードを書くより、実物からコードを起こす方が理解しやすかった
- 取り込みは、`plan`で結果を確かめてから`apply`できるので、`terraform import`コマンドより安全。何を取り込んだかもコードとして残る
- `plan`の差分を1つずつ読んで直していく作業は、「実物とコードの差」を知る一番の練習になった
