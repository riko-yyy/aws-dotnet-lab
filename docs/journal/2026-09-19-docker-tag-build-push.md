# 2026-09-19: docker build / tag / push の関係を勘違いしていた

## つまずいた箇所(誤解していたこと)
ECRにイメージをpushする際、`docker tag` でローカル用(`todo-api:local`)とECR用(`<ECRのURI>:latest`)の2つのタグを付けた。この時「pushがfrom/toを判断するために、ローカル側とレジストリ側の両方にタグが必要なのでは」「`docker build` の時点でリモートレジストリの情報が埋め込まれるのでは」と誤解していた。

## 実際の仕組み
- `docker build` はイメージの中身(レイヤー)を作るだけで、レジストリ情報は一切含まない。`-t` オプションは名前(タグ)を貼っているだけ
- タグの正体は `[レジストリのホスト名/]リポジトリ名[:バージョン]` という1本の文字列。ホスト名を省略するとDocker Hub宛てとみなされる
- `docker push <タグ>` は、その**1つのタグだけ**を見て「どのイメージを(ローカルでそのタグが指すもの)」「どこに(タグ内のホスト名)」送るかを両方決めている。from/to判断に2つのタグは不要
- 今回2つタグが必要だったのは、最初に `docker build -t todo-api:local .` とレジストリ情報を含まない名前でビルドしてしまっていたため。後からECRのURIを含む名前を `docker tag` で追加した
- 最初から `docker build -t <ECRのURI>:latest .` としていれば、`docker tag` のステップ自体不要だった

## 学び
Dockerの「タグ」はGitで言う「ブランチ名」や「リモート名」に近いラベルであり、イメージの実体(コンテンツ)とは独立している。1つの実体に複数のタグを付けられるのは、gitで1つのコミットに複数のブランチ・タグを指すことができるのと同じ発想。
