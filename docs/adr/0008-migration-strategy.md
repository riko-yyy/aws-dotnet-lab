# ADR-0008: EF Core Migrationの適用タイミング

## 論点
RDS(PostgreSQL)にテーブルを作成する際、EF Core Migrationをいつ・どうやって適用するか。

## 選択肢
- A案: アプリ起動時に自動適用する(`Program.cs`で`Database.Migrate()`を呼ぶ)
- B案: デプロイとは別の手順として、Migration専用の1回きりのタスク(`aws ecs run-task`でコンテナのコマンドを`dotnet ef database update`に上書き)を実行してから、Webサービス本体をデプロイする

## 決定
A案。アプリ起動時に自動でMigrateする。

## 理由
- 複数タスクが同時に同じMigrationを実行してレースコンディションになる懸念があるが、これは「同じバージョンのタスクが複数同時に起動する」場合(スケールアウト時)に限られる
- 今回は`Desired tasks: 1`(常に1台)の構成であり、ローリングデプロイ中に新旧タスクが一瞬並走することはあっても、新しいMigrationを実行しようとするのは新バージョンのタスクだけなので、競合が起こり得ない
- B案はCI/CDパイプラインの構築(一回きりのタスク実行ステップ)が必要になり、今の学習段階(RDS接続の理解)からスコープが広がる

## 却下した選択肢
- B案: 本番運用やスケールアウト構成ではこちらが定石とされる。タスクを複数台に増やす段階が来たら、その時点でA案からB案へ切り替えを検討する
