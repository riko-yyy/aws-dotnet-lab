# ADR-0018: 既存リソースをTerraform管理下に置く方法

## 論点
第1〜3段階で手動(コンソール)構築した既存のAWSリソース(VPC, ECS, RDSなど)を、Terraformの管理下に置くにあたり、どう進めるか。

## 選択肢
- A案: `terraform import`で、実在するリソースを1つずつTerraformの管理対象として取り込む。リソース自体は壊さず、実際の状態に合わせて`.tf`ファイルを書いていく
- B案: 既存のリソースを一旦全部手動で削除し、Terraformコードを書いてゼロから`terraform apply`で作り直す

## 決定
A案(`terraform import`)。

## 理由
- 実務では「既にあるものをTerraform管理下に持ってくる」場面(A案)が非常によくあり、学習価値としてこちらの方が実践的
- B案だとRDSの再作成待ち時間や、掃除の手間が余計に発生する
- 既存の動くシステムを壊さずに移行できる

## 却下した選択肢
- B案: 「更地から書く」練習にはなるが、今回は不要な手間とダウンタイムが発生するため見送った

## 実際にやってみて分かったこと
importは「リソースを1つずつ空の`resource`ブロックに紐付け→`terraform plan`で差分確認→差分が無くなるまでコードを実際の値に合わせて埋める」という反復作業になった。特に以下の点でつまずいた。
- `tags`のような属性は「コードに書かなければ削除される」扱いになる一方、`route`のような属性は「コードに書かなければ放置される」扱いになるなど、属性ごとに挙動が異なる(詳細は各journalを参照)
- `description`のようにForceNew(変更时に作り直しが必要)な属性は、デフォルト値との食い違いだけで「削除して作り直す」計画になり得るため、importしたら必ず`terraform plan`の内容を精査してから`apply`する必要がある
