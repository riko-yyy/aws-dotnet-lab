# ADR-0023: publicサブネットのルートテーブルはデフォルトを管理下に置く

## 論点
publicサブネット用のルートテーブルを、VPC作成時に自動生成されるデフォルトルートテーブルを流用するか、専用の`aws_route_table`を新規作成するか。

## 選択肢
1. `aws_default_route_table`でデフォルトを管理下に置く(現状)
2. `aws_route_table`を新規作成し、デフォルトは放置する

## 決定
1(デフォルトを管理下に置く)。

## 理由
VPCのデフォルトルートテーブルは削除できず、VPCが存在する限り必ず残り続ける。放置(選択肢2)すると、誰かが手動でAWSコンソールから変更してもTerraformが検知できない「管理外リソース」として残ってしまう。どうせ消せないものであれば、明示的にコードで管理下に置くほうが安全。

## 却下した選択肢
- 専用の`aws_route_table`を新規作成し、デフォルトルートテーブルは放置する案。

## 補足
privateサブネット用のルートテーブルは、VPC作成時に自動生成されないため`aws_route_table`の新規作成一択であり、publicと手法が異なるのは矛盾ではない。
