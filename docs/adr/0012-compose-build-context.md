# ADR-0012: ビルドコンテキストを `src/Todo.Api/` にする

## 論点
`docker-compose.yml`の`build.context`をリポジトリのどこに設定するか。

## 選択肢
- `./src/Todo.Api`(現状)
- リポジトリ直下 `.`(Docker公式の[.NETガイド](https://docs.docker.com/guides/dotnet/)の例)

## 決定
`./src/Todo.Api`のまま。

## 理由
今はAPIプロジェクト単体で`COPY`に必要なファイルが完結しており、ビルドコンテキストをリポジトリ直下まで広げる理由がない。公式ガイドがリポジトリ直下をcontextにしているのは、テストプロジェクトなど複数のプロジェクトを1つのDockerfileから扱うケースを想定しているためで、うちの現在の構成には当てはまらない。

最終ステージが1つで、公式ガイドのような開発用の中間ステージ(`development`)も無いため、`target`オプションの指定も不要。

## 却下した選択肢
- リポジトリ直下: 不要に広い範囲をビルドコンテキストに含めることになり、`.dockerignore`の管理も煩雑になる

## 見直しの条件
コンテナ内でテスト(`dotnet test`)を実行したくなった場合など、複数プロジェクトを1つのビルドで扱う必要が出てきたら、contextをリポジトリ直下に広げ、`dockerfile:`でDockerfileの場所を明示する。
