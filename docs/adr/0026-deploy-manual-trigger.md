# ADR-0026: デプロイの発火条件は手動実行(workflow_dispatch)のみにする

## 論点
GitHub Actionsによるデプロイを、どのタイミングで実行するか。

## 選択肢
- A案: `workflow_dispatch`による手動実行のみ
- B案: mainブランチへのpush(マージ)で自動デプロイ

## 決定
A案(手動実行のみ)。

## 理由
- 個人の学習用ラボであり、常時デプロイし続ける必要がない
- ECSサービスの`desired_count`は基本0(ADR-0020)で、動作確認のタイミングも自分でコントロールしたい。自動デプロイにすると「いつタスクが起動するか」が読みにくくなり、コスト管理と相性が悪い
- 実務でのCI(pushで自動ビルド・テスト)とCD(承認を挟んでデプロイ)の役割分担のうち、CD側を手動にする構成は、本番運用でも承認ゲートとしてよく使われる考え方であり、学習として不自然ではない

## 却下した選択肢
- B案(push自動デプロイ): 実務でもよくある構成だが、上記のコスト・運用上の理由で今回は見送り。CI(ビルド確認)だけをpushで自動化し、デプロイのみ手動にする構成は将来的に検討の余地あり
