# ADR-0023: IAM Access Analyzer(外部アクセス分析)を導入する

## 論点
なぜこのタイミングでIAM Access Analyzerを導入するか。

## 背景
`main.tf`にSecretsManagerのARNとAWSアカウントIDを平文でハードコードし、公開リポジトリにそのままコミットしてしまう出来事があった([ADR-0022](0022-secretsmanager-arn-dynamic-reference.md))。ARN自体はIAMの権限チェックがある限り実害は小さいが、「気づかずに公開状態のものをコミットしてしまう」というミスの再発を防ぐ仕組みが欲しくなった。

## 決定
外部アクセス分析(External Access Analyzer)を有効化し、アカウント内のリソースが意図せず外部(他アカウントやインターネット)からアクセス可能になっていないかを継続的にチェックする。

## 理由
無料で使え、Terraformでインフラをコード化する中で増える「IAMロールやセキュリティグループの設定ミスに、自分で気づけない」リスクに対する安全網になる。ARNのようなハードコードのミスそのものは検知対象ではないが、それが引き起こしうる実際の外部公開(意図しないIAMロールの信頼関係、公開設定のS3バケットなど)は検知できる。

## 却下した選択肢
- 未使用アクセス分析(Unused Access Analyzer): 90日間のみ無料で以降課金対象のため見送り(詳細は[ADR-0024](0024-iam-access-analyzer-scope.md))。

## 補足
Access Analyzerが直接検知するのは「外部アクセス可能な状態」であり、「ARNなどの値がコードやリポジトリに書かれていること」自体は検知しない。ARNのハードコード自体はIAMポリシーで許可先を絞っていたため外部アクセスの直接原因ではなかったが、「気づかないうちに公開範囲が広がるミス全般」への備えとして導入する。
