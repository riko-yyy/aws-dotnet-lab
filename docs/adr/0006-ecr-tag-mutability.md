# ADR-0006: ECRのタグ運用(Tag Mutability)

## 論点
[`:latest`タグに新しいイメージをpushしたのに、ECSが古いイメージのまま起動する事象](../journal/2026-09-19-ecs-stale-image-latest-tag.md)が発生した。これを受けて、ECRリポジトリのタグ運用をどうするか。

## 選択肢
- A案: ECRリポジトリを`IMMUTABLE`(タグ変更不可)に切り替え、pushのたびにコミットハッシュやバージョン番号など新しいタグを使う運用に変更する
- B案: 現状の`MUTABLE`(デフォルト)のまま、`:latest`タグを使い続ける。ただしデプロイ時は`--force-new-deployment`を徹底する

## 決定
B案。`MUTABLE`のまま維持する。

## 理由
- 本リポジトリは学習用途であり、厳密なバージョン管理やロールバックの仕組みまで今の段階で作り込む必要性は薄い
- A案に切り替えるとタグ運用(バージョニング戦略)の設計が別途必要になり、今の学習段階(ECS Fargateの理解)からスコープが広がりすぎる
- 今回の問題自体は`--force-new-deployment`で回避可能であり、当面の学習の支障にはならない

## 却下した選択肢
- A案(Immutable化): 将来的に採用する価値はあるが、今回は見送り。第5段階(GitHub Actionsによる自動デプロイ)でCI/CDのタグ戦略(コミットハッシュタグなど)を設計するタイミングで改めて検討する
