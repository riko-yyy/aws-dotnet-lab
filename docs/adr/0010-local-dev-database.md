# ADR-0010: ローカル開発用データベースの追加

## 論点
RDSはプライベートサブネットに置いているため、ローカルの`dotnet run`から直接接続できない。ローカルでAPIを動かしながらDBありの動作確認をしたい場合、どうするか。

## 選択肢
- A案: Docker Composeでローカル専用のPostgreSQLコンテナを立て、APIコンテナと一緒に起動する
- B案: `docker run`でPostgreSQLコンテナを都度手動起動する
- C案: Homebrewなどでホストマシンに直接PostgreSQLをインストールする

## 決定
A案。`docker-compose.yml`でAPI用コンテナとPostgreSQL用コンテナをまとめて定義し、`docker compose up`一発で両方起動する。

## 理由
- 既にDockerイメージ・Dockerfileの知識があるため、学習の連続性がある
- `docker run`を毎回手打ちする(B案)より、設定をファイルに残せて再現性が高い
- ホストへの直接インストール(C案)は環境を汚し、チーム開発を想定した場合の再現性にも欠ける
- Composeが持つ「サービス名がそのままDNS名になる」機能により、接続情報を複雑にせず済む(`Db__Host=db`)

## 却下した選択肢
- B案: 手軽だが、起動コマンドやネットワーク設定を毎回覚えておく必要があり非効率
- C案: OSに依存する手順になり、かつ本番(RDS)と実行環境の差異が大きくなる
