# ADR-0003: ディレクトリ構成

## 論点
今後Terraform(インフラのコード化)やADR、つまずきログが増えていく前提で、リポジトリのディレクトリをどう構成するか。

## 選択肢
- リポジトリ直下にAPIプロジェクトを直接置く(フラットな構成)
- `src/` (アプリケーションコード) と `docs/` (ADR・ログ) を分離する構成

## 決定
以下の構成にする。
```
src/Todo.Api/      # .NET プロジェクト
docs/adr/          # ADR
docs/journal/       # つまずいた箇所・原因・解決のログ
```
`infra/` はTerraform導入(第4段階)のタイミングで追加する。

## 理由
- 第4段階でTerraformコードが、第5段階でGitHub Actionsの設定が増える見込みがあり、最初からアプリケーションコードと切り離しておいた方が後の変更が少ない
- ADRとつまずきログはコードと寿命・更新頻度が異なるドキュメントなので、`docs/` 配下にまとめて分離する

## 却下した選択肢
- フラットな構成: 現時点ではシンプルだが、Terraformコードやドキュメントが増えた際にリポジトリ直下が煩雑になるため却下
