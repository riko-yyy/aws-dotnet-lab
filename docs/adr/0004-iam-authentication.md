# ADR-0004: AWS認証方式

## 論点
第2段階(ECS Fargateへのデプロイ)以降、ローカルからAWS CLI/Terraformを使って操作する。その際の認証方式をどうするか。

## 選択肢
- A案: IAMユーザーを作成し、長期のアクセスキー(プログラムアクセス用)を発行してCLIに設定する
- B案: IAM Identity Center(旧AWS SSO)を使い、一時的な認証情報でCLIを使う
- rootアカウントをそのまま使う

## 決定
B案。IAM Identity Centerを使い、`aws sso login` で発行される一時認証情報でCLI/Terraformを操作する。

## 理由
- アクセスキー(A案)は長期間有効な認証情報であり、漏洩時のリスクが大きい。AWSも非推奨の方向に舵を切っている
- IAM Identity Centerは現在のAWS推奨方式であり、実務でも主流になりつつあるため学習価値が高い
- 個人の学習用ラボとはいえ、認証まわりは実務に近い形で経験しておきたい

## 却下した選択肢
- IAMユーザー+アクセスキー: セットアップは簡単だが、長期認証情報を扱う運用に慣れてしまうデメリットの方が学習目的において大きいと判断
- rootアカウント: 権限が強すぎて誤操作時の被害が大きく、どちらを選んでも避けるべき運用のため選択肢から除外
