# ADR-0009: ECSタスクの実行ロールをタスクごとに専用化する

## 論点
ECSタスクがRDSのパスワード(Secrets Manager)を読めるようにする権限を、どのIAMロールに持たせるか。

## 選択肢
- A案: 既存の共有ロール `ecsTaskExecutionRole`(AWSが自動生成する汎用の実行ロール)に、Secrets Manager読み取り権限を追加する
- B案: `todo-api-task` 専用の新しい実行ロールを作成し、そこに「標準の実行権限(ECR pull・ログ書き込み)+このシークレットの読み取り」だけを持たせる

## 決定
B案。`todo-api-task` 専用の実行ロールを新規作成する。

## 理由
- IAMロールの権限は「そのロールを実行時に使うすべてのタスク・サービス」に及ぶ。`ecsTaskExecutionRole` は名前の通り汎用の共有ロールであり、今後別のタスク定義(このプロジェクト内・別プロジェクトを問わず)が同じロールを指定した場合、そのタスクも今回のRDSシークレットを読めてしまう
- これは最小権限の原則(riko-userの権限設計、ADR-0004と同じ考え方)に反する
- タスクごとに専用ロールを作ることで、権限の影響範囲をそのタスクだけに閉じ込められる

## 却下した選択肢
- A案: 手軽だが、権限の漏れが設計上組み込まれてしまう。一度CLIで誤ってこの方法を実施してしまったが、ユーザーの指摘で気づき、ロールを分離する方針に修正した
